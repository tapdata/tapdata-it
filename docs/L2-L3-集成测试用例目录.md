## 0. 如何使用本文档（研发人员必读）

1. **认领**：每条用例有 `编号 / 用例名 / 验证点 / 方法要点 / 优先级 / 状态 / 认领人`。认领时在 `认领人` 填你的名字，`状态` 改为 🔄。
2. **状态图例**：⬜ 待建 ｜ 🔄 进行中 ｜ ✅ 已实现并可运行 ｜ 🚫 废弃/重复。
3. **落地位置**：
   - L2 用例 → `manager/tm/src/it/java/...`（跨模块，真实 TM + 引擎），命名 `*IT.java`。
   - L3 用例 → 新建 `tapdata-it/product-e2e`（薄黄金路径）与 `tapdata-it/product-stability`（HA/长跑专项）。
4. **编号规范**：`L2-{模块字母}-{两位序号}`（如 `L2-A-01`）；`L3-F-{序号}`（功能）/ `L3-S-{序号}`（稳定性）。**编号一经分配不复用**，废弃标 🚫。
5. **门禁归属**：L2 合并 `develop/release-v*` 时必跑（红即阻断）；L3-F 发布前 RC 门禁；L3-S 定时跑、告警但不阻断发布。
6. **积累原则**：改哪个模块的代码，就在对应模块补/更新该模块的 L2 用例——**DoD（完成定义）的一部分**。

# 第一部分：L2 面向产品服务组件的跨模块集成测试

## 1.1 L2 测试载体与运行方式

L2 验证"**两个及以上模块协作后的产品能力**"，是"单测很多但抓不到系统集成问题"的主战场。核心是把验证**压回构建内**，不依赖整套已部署产品：

| 维度 | 方案 |
|---|---|
| **拉起方式** | `@SpringBootTest` 启动**真实 TM**（`manager/tm`，内嵌/容器 MongoDB 作 metadb）+ 在同进程或受管进程内启动**引擎 iengine**，引擎经**真实 WebSocket** 注册到 TM |
| **对端数据库** | Testcontainers 动态拉起 MySQL / MongoDB 等源、目标库，用完销毁 |
| **驱动方式** | ① TM REST API（由 `tm_api.json` 1121 路径契约生成**类型化客户端**）；② 直接触发 WebSocket 命令事件（`WebSocketEvent`）验证 RPC |
| **断言方式** | ① **旁路直连**目标库核对数据事实（禁止用 read 验 write）；② 查询 TM 状态接口/状态机；③ 断言 WebSocket 回报事件（`WebSocketResult`）；④ 校验 metadb 落库 |
| **可复用资产** | `MockTM`（Undertow 双协议，反转为真实 TM 的对照）、`ConnectorVerifier` 旁路验证器、`EngineCodecs` 编解码、`ConnectionConfigLoader` 连接配置加载 |
| **Flaky 治理** | 不稳定用例打 `@Tag("flaky")` 从门禁剔除、单列看板、指派 Owner + 修复 SLA，保证"红灯=真问题" |

> **代码锚点**：TM 侧 WebSocket RPC 在 `manager/tm/.../ws/`（`WebSocketHandler` / `WebSocketServer` / `WebSocketClusterServer` / `WebSocketManager` + `@WebSocketMessageHandler` 注解派发）；引擎侧命令处理在 `iengine-app/.../io/tapdata/websocket/handler/`（14 个 `*EventHandler`）。

# 第二部分：L3 完整产品自动化测试框架

## 2.1 L3 框架设计（动态启动完整产品）

L3 验证"**完整产品端到端**"，替代旧 `t-layer3-test`。与旧框架的根本区别在于**位置与所有权**，而非语言：

| 对比项 | 旧 t-layer3-test | 新 L3 框架 |
|---|---|---|
| 环境 | 手工部署的固定环境 | **一键动态启动**完整产品（容器编排），用完销毁 |
| 位置 | 独立仓库、构建之外 | 纳入 `tapdata-it`，**发布前 RC 门禁** |
| 驱动 | 手写脆弱 REST | **契约化类型客户端**（`tm_api.json` 1121 路径 + `server_api_definition.json` 生成） |
| 所有权 | QA 独有、与研发脱节 | SDET 主导 + 研发共建，与产品同栈（JVM） |
| 运行 | 单台 macOS runner | 自托管 runner 池（复用 `tapdata-it` label），去单机瓶颈 |

**框架能力要求**（对应你的诉求）：① 动态启动完整 TapData（所有组件）；② 执行数据复制/同步/校验等完整集成用例；③ 具备 HA/failover 稳定性 + 主流程功能自动化。

| 维度 | 方案 |
|---|---|
| **组件编排** | 基于 `deploy/docker/docker-compose.yaml` + Testcontainers 网络，一键拉起：metadb(MongoDB)、TM(manager)、**iengine（可多副本，供 HA）**、API Server、Hazelcast 集群、frontend(web)、connectors、agent、externalStorage、license |
| **驱动方式** | 契约客户端封装产品操作 DSL：`建数据源 → 建任务(migrate/sync) → 启动 → 源端写入 → 查询状态/目标端` |
| **断言方式** | ① **旁路直连**源/目标库核对数据事实；② 查询产品 API 任务/校验状态；③ 采样指标（QPS/延迟/CPU/内存）对比基线 |
| **用例分级** | `case_type`：s=冒烟(黄金路径) / f=功能 / h=HA稳定性 / p=性能 |
| **报告与通知** | 汇总报告页 + 飞书群失败推送（复用现有 chat_id 通知链路） |
| **模块划分** | `product-e2e`（L3-F/S 门禁与冒烟）＋ `product-stability`（L3-H/P 定时专项） |

> 门禁归属：**L3-F/s** 纳入发布前 RC 门禁（黄金路径必绿）；**L3-H/p**（HA/长跑/性能）定时跑、告警但**不阻断发布**（24h 长跑不应卡住每次发版）。
